# DD4 전개 계산기 — 사이트 이식 안내 (Claude Code용)

이 폴더의 Python 코드가 `dd-handtraps.json`, `dd-planlib.json`, `dd-smallworld.json`을 만든 계산기다.
목표: 이 계산기를 JavaScript로 옮겨서, 사이트가 **실제 패를 받을 때마다 그 자리에서** 수순과 패트랩 대응을 계산하게 한다.
그러면 미리 만든 데이터의 한계("패에 이니시만 있다고 가정", "3종 이상 겹치는 패는 계산 안 함")가 없어진다.

## 파일

| 파일 | 역할 |
|---|---|
| `checker.py` | 카드 상태 모델과 단계 문장 해석기. `State`(덱·패·필드·P존·계약서·묘지·제외·엑덱 앞면·엑덱, 1턴 제약 카운터, 일반소환 수, 드롤 잠금, DD만 특소 제약, P소환 횟수)와 `handle(st, i, 문장)` |
| `engine.py` | 계산기 본체. `step()`(한 단계를 트랜잭션으로 실행, 실패하면 상태 그대로), 효과 분류 `classify()`, 몬스터 존 추적(링크 마커), 대체 단계 생성 `_alts()`, 수순 재생 `run_steps()`(대안 비교 lookahead 포함), 이어 붙일 수순 찾기 `best_continuation()`, 점수 `score()`, 필드 요약 `describe()` |
| `hits.py` | 패트랩 11종 모델과 단계별 적용 `simulate()` |
| `handadjust.py`, `planlib.py`, `fillgaps.py`, `smallworld.py`, `deckpulls.py` | 데이터 파일을 만드는 스크립트(이식 후엔 참고용) |
| `dd-routes.md` | 루트 29개 원문. 계산기는 이 단계 문장 문법을 그대로 해석한다 |
| `fixtures/*.json` | 이식 검증용 정답 데이터(아래) |

## 핵심 동작 (이식할 때 그대로 지킬 것)

1. **단계 = 문장.** 모든 행동은 dd-routes.md의 문장 형식("코페르 서치(카운트 효과)", "빌가메스 링크(카운트+케플러)" 등)이고, `handle()`의 정규식이 해석한다. 문장 문법을 바꾸지 말 것.
2. **트랜잭션.** `step()`은 상태를 복사해서 실행하고, 규칙 위반(`issues`)이 생기면 원래 상태를 돌려준다. `[룰확인]` 등 `IGNORE` 목록은 위반으로 안 친다.
3. **몬스터 존.** 2020년 룰 기준: 링크 몬스터와 엑덱 앞면 펜듈럼만 EX 몬스터 존이나 링크 마커가 가리키는 메인 존에. 융합·싱크로·엑시즈는 아무 메인 존. 마커: 빌가메스·비욘드 = 왼쪽 아래·오른쪽 아래, 제우스 = 왼쪽 아래·아래·오른쪽 아래. 가능한 배치 전부를 집합으로 들고 다니다가 비면 실패.
4. **소환 수.** 니비루 조건은 소환한 몬스터 "장수". `State.summon` 호출 + 필드 차이로 센다(같은 단계에서 나왔다 사라진 것, 같은 이름 교체도 셈).
5. **대체.** 단계가 실패하면 `_alts()`가 대상·소재·P소환 조합·서치 대상을 바꾼 문장을 만든다. 일반 모드는 처음 성공한 것, lookahead 모드는 최대 4개를 끝까지 돌려 최종 점수가 높은 것.
6. **추가 트리거.** lookahead 모드에서 DDD·계약서가 파괴된 직후 `제로마키나 특소(제로마키나 효과)`, 자신이 데미지를 받은 직후 `오르트로스 특소(오르트로스 효과)`(패에 있을 때)를 끼워 넣어 보고 좋으면 채택("(추가)" 표시).
7. **이어 붙이기.** `best_continuation(상태, own=(루트, 시작단계))`: 자기 루트 나머지 + 29개 루트 각각에서 지금 상태와 가장 비슷한 위치(카드 위치 차이 가중합)부터의 나머지를 전부 재생해 최고 점수를 고르고, 상위 2개는 lookahead로 다시 돌린다.
8. **점수.** 제우스·사이프리트·대왕시져·데스마키나 각 3, 아크 크라이시스 1.5, 솔로몬 1, 상암 내성(P존 2장) 2, 엑덱 제로마키나 대기 1.5, 그 외 0.3~0.8. 무효 상태 몬스터는 ×0.3.

## 사이트에서의 사용

- 패 입력 → (스몰 월드가 있으면 dd-smallworld.json 경로마다 패를 바꿔서) → 이니시가 맞는 루트마다 `best_continuation(init_state(패), own=(루트,1))` → 최고 점수 수순 표시.
- 패트랩 버튼 → 지금 수순의 n단계에 `hits.py`의 `simulate()`와 같은 처리 → 결과 수순 표시.
- 계산은 Web Worker에서. Python 기준 `best_continuation` **한 번**이 0.1~0.5초이고, 패 하나는 시작 카드가 맞는 루트 수만큼 반복하므로 **수 초**(Claude Code 측정 약 7.7초)가 걸린다. (정정: 이전 판은 "한 번에 0.1~0.5초"만 적어서 패 하나 시간처럼 읽혔음)
- 속도 대책(권장 순서):
  1. 패를 넣으면 먼저 `dd-planlib.json` 장수 검사 결과를 즉시 보여주고, 계산기 결과가 나오면 더 좋을 때만 교체(점진 표시).
  2. 루트별 `best_continuation` 호출은 후보 수순 대부분이 겹친다. 패 하나에 후보 목록을 한 번만 만들고(각 루트의 1단계 시작 + 루트별 가장 가까운 위치) 한 번에 재생하면 반복이 줄어든다. 단 이건 이식 과정의 최적화 아이디어이고 Python에서 결과가 같은지 아직 확인 안 했으니, fixtures/hands.json 점수가 그대로인지 확인한 뒤에만 쓸 것.
  3. 스몰 월드는 경로마다 계산기를 돌리지 말고 `dd-planlib.json` 장수 검사로 고른 뒤, 최종 후보 1~2개만 계산기로 확인.
- 거리 계산을 정수로 바꿀 때는 반올림하지 말고 가중치(1.0·0.8·0.6·0.4)에 10을 곱해서 정수로 만들 것. 반올림하면 후보 순위가 바뀌어 fixtures와 어긋날 수 있다.
- 미리 만든 JSON은 이식 전·후 비교와 계산 실패 시 대비용으로 남겨둔다.

## 이식 검증 (fixtures)

- `fixtures/routes.json`: 29개 루트를 시작 패로 돌린 결과(실패 단계 없음, 최종 필드).
- `fixtures/hands.json`: 무작위 패 40개 → 기대 최고 점수·최종 몬스터. (정정: 이전 판에 200개라고 적었으나 생성 시간 때문에 40개로 줄였음)
- `fixtures/handtraps.json`: 패트랩 레코드 200개 → 기대 최종 점수·몬스터.

JS 결과가 fixtures와 다르면 Python 쪽 동작을 기준으로 맞출 것. 점수는 ±0.01까지 같아야 한다.

## 알려진 한계 (이식해도 그대로)

- 블로그 루트 29개의 수순을 재조합하는 방식이라, 결과는 "최소 이만큼은 된다"는 하한이다.
- MD 실기 확인 안 함.
- 상대 패트랩은 1장 기준.
