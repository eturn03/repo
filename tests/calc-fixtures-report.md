## 원인과 동점 규칙 고정

후보 위치 거리가 같을 때 (루트 id, 단계 번호) 순으로 고정하는 규칙을 Python(`tests/fixtures/python-pinned.patch`)과 JS에 똑같이 넣고 다시 비교했다. 결과(`tests/fixtures/python-pinned-seeds.txt`):

- **거리 동점 규칙만 넣은 Python**: 시드마다 결과가 원래 Python과 똑같이 바뀐다. 이 13건의 원인은 거리 동점이 아니다.
- **원인**: 같은 루트 수순을 다시 돌릴 때, 단계가 막히면 대체 후보 중 처음 성공한 것을 쓰는데(lookahead 아닌 모드), Python은 후보를 `sorted(set(...), key=비용)`으로 만든다. 비용이 같은 후보끼리는 set 순서(해시 시드)를 따라서 실행마다 다른 대체를 고른다. 예: F5 13 니비루에서 F1 14단계부터 재생한 점수가 Python 시드 0은 5.4, JS는 8.1.
- **대체 후보 동점 규칙도 고정**(처음 나온 순서, Python은 `dict.fromkeys`, JS는 원래 이 방식): Python 시드 0·1·2·5 모두 같은 결과가 나오고 14건 모두 JS와 같다.
- 두 규칙을 고정한 Python으로 fixtures 전체를 시드 0·3에서 다시 돌림(두 시드 결과 같음): **routes 29/29, hands 40/40(고른 수순까지 40/40), handtraps 200/200**이 JS와 같다. 결과는 `tests/fixtures/python-pinned.json`, 비교는 `node tests/calc_fixtures.cjs` 끝부분.
- 참고: 고정 전 Python은 119번에서 시드에 따라 9.6이 나와 JS(9.3)보다 높을 때가 있었다. 고정판에서는 9.3으로 같다. 같은 비용의 대체를 다른 순서로 고르면 더 좋은 수순이 나올 수 있다는 뜻이라, "처음 성공한 대체"가 최선을 보장하지는 않는다(하한이라는 한계와 같은 이야기).
