## 1. 무엇을 만드나

구글 시트 "돈관리"를 원본으로 하는 웹앱 하나. 쓰는 사람은 사용자 한 명.

| 기기 | 역할 |
|---|---|
| 아이폰 위젯 | 열지 않아도 "오늘까지 쓸 수 있는 돈"과 가장 가까운 마감 한 줄이 보인다 |
| 아이폰 웹앱 | 위젯을 누르면 열린다. 지출과 할 일을 입력한다 |
| 맥북 보드 | 외부 모니터에 항상 띄워 둔다. 맨 위에 오늘까지 쓸 수 있는 돈. 입력도 된다 |
| 맥북 분석 탭 | 보드에서 눌러 들어간다. 빚 완료일, 분류별 지출, 자산 변화, 예산 대비 위치 |

**성공 기준:** 2주쯤 실제 지출을 기록한다 → 그 기록으로 등교일 예산을 다시 정한다 → 그 예산 안에서 한 주기(한 달)를 끝낸다.

**만드는 순서:** 1차 지출 입력·위젯·맥북 보드 → 2차 할 일 → 3차 분석 탭. 단계마다 사용자가 실제로 써 보고 승인한 뒤 다음으로 간다.

**범위 밖:** 캘린더, 루틴, D-day, 커리큘럼, 은행 자동 연동, 네이티브 아이폰 앱, 폰이 울리는 알림, 투자 시세 반영.

| 환급·장학금 | 전액 상환 |
| 자산 표시 | 카드 미결제액, 아직 안 나간 구독료, 남은 빚을 미리 뺀 값으로 보여 준다 |
| 맥북 | 항상 띄운 보드 한 화면 + 눌러서 들어가는 분석 탭 |

## 3. 돈 규칙

계산은 전부 `apps-script/Calc.js`의 순수 함수가 한다(시트 수식이 아니다). 서버·브라우저·테스트가 같은 파일을 쓴다. 시트에는 손으로 넣는 값과 기록만 둔다.

### 3.1 오늘까지 쓸 수 있는 돈 (등교일 예산 이월, 사용자 정의)

```
주기          = 주기시작일(설정)부터 한 달. 지금은 매월 1일 ~ 말일
등교일        = 설정의 등교요일에 해당하고 방학 탭의 기간 밖인 날. 나머지는 쉬는 날
기본 주기 예산  = 등교일예산(설정) × 주기의 등교일 수 + 쉬는날예산(설정, 기본 0) × 주기의 쉬는 날 수
주기 예산      = 기본 주기 예산 + 이 주기에 들어가는 비정규 쓸 돈 몫(3.6)
오늘까지 쓸 돈  = 등교일예산 × 오늘까지의 등교일 수 + 쉬는날예산 × 오늘까지의 쉬는 날 수
               + 오늘까지 쌓인 비정규 쓸 돈 몫(3.6) − 이번 주기 예산 지출
이번 달 남은 돈 = 주기 예산 − 이번 주기 예산 지출
예산 지출      = 지출 탭에서 분류가 `교통`이 아닌 행
```

안 쓴 돈은 다음 날로 넘어가고, 많이 쓰면 다음 날들 몫에서 빠진다. "오늘"은 시트 시간대(Asia/Seoul) 기준이다. 공휴일은 따로 빼지 않는다.

예산은 등교일에만 쌓인다(2026-11-10 사용자 결정). 사용자는 등교일에만 돈을 쓰는데, 매일 똑같이 쌓으면 계획대로 쓰고 있어도 주중 내내 숫자가 마이너스로 보이기 때문이다. `쉬는날예산`은 방학처럼 등교일이 없는 기간을 위해 둔 값이고 평소에는 0이다.

검증 예시(테스트에 그대로 넣는다):
- 등교요일 월~목, 등교일예산 5,000원(예시 숫자). 월요일 5,000원, 5,000원을 쓰면 0원. 화요일에 다시 5,000원. 월요일에 3,000원만 쓰면 화요일은 7,000원. 금·토·일에는 숫자가 변하지 않는다.
- 등교요일을 매일로 두고 등교일예산 1,000원이면(사용자가 처음 준 예시와 같다) 1일 1,000원, 2일 2,000원. 2일에 1,500원을 쓰면 3일은 1,500원.

"등교일 예산"과 "오늘까지 쓸 수 있는 돈(누적)"은 화면에서 이름표를 분명히 달리한다. 예전에 사용자가 둘을 헷갈렸다.

### 3.2 교통 차감

```
교통 차감     = 실제 교통 지출 합계(주기 시작 ~ 교통대조일)
             + 등교일당교통비(설정) × 등교일 수(교통대조일 다음 날 ~ 주기 끝)
```

등교일은 3.1의 정의를 쓴다. 교통대조일이 주기 시작보다 앞이면 전부 예상치다. 교통 지출은 사용자가 직접 입력하지 않는다. 대조 때 Claude가 카드 내역에서 찾아 분류 `교통`으로 넣고 교통대조일을 갱신한다.

### 3.3 월 상환 가능액

```
월 상환 가능액 = 월수입(설정) − 구독 합계(고정비 탭) − 교통 차감 − 기본 주기 예산
```

음수면 화면이 "예산이 수입을 넘는다"고 알린다. 교통을 덜 쓰면 그 차이는 상환 가능액으로 간다(등교일 예산은 그대로).

남은 빚 = 빚원금(설정) − 상환 탭 합계. 빚은 사용자 본인 목돈에서 당겨 쓴 돈이라 기한·이자가 없다.

### 3.4 등교일 예산을 다시 정하는 시점

설정의 `기록시작일`부터 14일이 지나면 보드의 상태 문장이 "등교일 예산을 다시 정할 때"라고 알린다. 사용자가 새 등교일 예산을 정하면 `예산확정일`에 날짜를 적는다. 성공 기준은 그 뒤 첫 온전한 주기에서 이번 달 남은 돈이 0 이상으로 끝나는 것이다.

### 3.5 자산 (3차, 초안)

3차를 시작할 때 사용자와 다시 확인한다. 계좌별 잔고를 아직 받지 못했다.

```
계좌 현재 금액 = 기준 금액(자산 탭) − 기준일 뒤 그 수단으로 쓴 지출
              − 기준일 뒤 결제일이 지난 구독료(그 수단) + 기준일 뒤 주기 시작일마다 월수입(입금 계좌)
카드 미결제   = 기준 금액 + 기준일 뒤 카드 지출
실제 내 돈    = 통장·현금 합계 + 투자 고정값 − 카드 미결제 − 이번 주기에 아직 안 나간 구독료 − 남은 빚
```

기준 금액과 기준일은 주 1회 대조 때 실제 잔고로 다시 맞춘다. 구독료 결제일 앞뒤로 "실제 내 돈"이 튀지 않는 것이 이 식의 목적이다.

### 3.6 비정규 수입 (2026-11-10 사용자 결정)

`수입` 탭에서 종류가 `비정규`인 행마다:

```
쓸 돈 몫   = min(금액, 비정규쓸돈(설정))
상환 몫    = 금액 − 쓸 돈 몫
나누는 날  = 들어온 다음 날부터 30일 사이의 등교일 (N일)
어느 날까지 쌓인 몫 = floor(쓸 돈 몫 × 그날까지 지난 나누는 날 수 ÷ N)
```

- 30일 사이에 등교일이 하나도 없으면(방학) 30일 전체에 날마다 똑같이 나눈다.
- 나누는 날이 두 주기에 걸치면 각 주기에는 그 주기 안의 몫만 들어간다. 주기 예산(3.1)에는 그 주기 몫 전체가, 오늘까지 쓸 돈에는 오늘까지 쌓인 몫이 더해진다.
- 상환 몫은 사용자가 실제로 목돈에 옮긴 뒤 `상환` 탭에 적는다. 월 상환 가능액(3.3)은 이 수입과 무관하다.
- 종류가 `환급`·`기타`인 행은 쓸 돈에 더하지 않는다. 전액이 상환 대상이다.

## 4. 구조

```
구글 시트 "돈관리" ── Apps Script 웹앱 ──┬── 웹앱 (GitHub Pages, 폰·맥북 공용)
   (값과 기록)        (Calc.js로 계산)     └── 아이폰 위젯 (Scriptable)
```

프레임워크·빌드 도구·런타임 의존성 없이 정적 HTML/CSS/JS로 쓴다. 사용자가 코드 비전문가라 수정도 Claude가 맡기 때문이다.

### 4.1 파일

```
index.html, css/style.css      화면
js/config.js                   서버 주소 등 (비밀값 없음)
js/app.js                      시작, 토큰, 갱신, 화면 전환
js/…                           필요하면 화면별로 나눈다 (입력, 보드, 분석)
apps-script/Calc.js            돈·할 일 계산. 순수 함수. 서버·브라우저·테스트 공용
apps-script/Code.js            웹앱 입구, 시트 읽기·쓰기
tests/*.test.js                Calc 테스트
widget/money-widget.js         Scriptable 위젯 (토큰은 기기 키체인에)
.claude/skills/card-reconcile/ 주 1회 카드 대조 절차
docs/SETUP.md, docs/SHEET.md   사용자용 설치 안내, 시트 구조
tasks/plan.md, tasks/todo.md   이 문서, 작업 목록
local-notes/                   실제 값 (git이 무시)
```

`Calc.js`는 `var Calc = (function () { … })();` 한 덩어리로 쓰고 끝에 `if (typeof module !== 'undefined') module.exports = Calc;`를 둔다. Apps Script는 모듈이 없고, 브라우저는 `<script>`로, Node는 `require`로 읽는다. 브라우저가 이 파일을 읽는 이유는 예시 모드와, 입력 직후 서버 응답을 기다리지 않고 같은 식으로 숫자를 다시 그리기 위해서다.

### 4.2 시트 탭 (v2)

1행은 제목, 2행부터 데이터. 이름이 `_`로 시작하는 탭은 서버가 읽지 않는다.

| 탭 | 열 | 비고 |
|---|---|---|
| `설정` | 항목, 값, 설명 | 월수입, 등교일예산, 쉬는날예산, 주기시작일, 등교요일, 등교일당교통비, 빚원금, 투자고정값, 확률성수입, 비정규쓸돈, 분류(쉼표 목록), 기본수단, 수입계좌, 기록시작일, 예산확정일, 마지막대조일, 교통대조일 |
| `지출` | id, 날짜, 금액, 분류, 수단, 메모, 출처, 입력시각 | 출처는 `앱` 또는 `대조` |
| `고정비` | 이름, 금액, 결제일, 수단, 메모 | 구독만. 교통 행은 없앤다 |
| `자산` | 이름, 종류, 금액, 기준일, 메모 | 종류: 통장, 현금, 투자, 카드. 통장·현금·카드 행의 이름이 결제 수단 목록이 된다 |
| `상환` | 날짜, 금액, 메모 | 목돈에 갚은 기록 |
| `수입` | 날짜, 금액, 종류, 메모 | 월수입 밖에서 들어온 돈. 종류 `비정규`는 쓸 돈 몫을 뗀다(3.6). `환급`·`기타`는 전액 상환 대상 |
| `방학` | 시작일, 끝일, 메모 | 이 기간은 등교일 0 |
| `할일` | id, 제목, 마감일, 완료일, 종류, 키, 회차, 메모, 입력시각 | 2차. 종류는 `일반` 또는 `자동` |
| `반복` | 키, 제목, 주기, 기준, 미리표시일수 | 2차. 자동으로 뜨는 돈 관련 할 일 규칙 |
| `자산기록` | 날짜, 실제내돈, 남은빚, … | 3차. 주 1회 이상 스냅샷 |

옛 `설정` 탭의 수식 행(자동 계산)과 `저축목표`, `건당한도` 항목은 없앤다. 탭 구조를 바꾸기 전에 드라이브에 시트 사본을 만든다.

### 4.3 서버 요청

POST 하나로 받는다. 본문은 JSON 문자열 `{"token": "...", "view": "...", …}`, `Content-Type`은 `text/plain`(브라우저 사전 확인 요청을 피한다). 토큰이 틀리면 `{}`만 돌려준다. GET은 항상 `{}`.

| view | 단계 | 받는 값 | 돌려주는 값 |
|---|---|---|---|
| `summary` | 1차 | — | 화면에 필요한 계산 결과 전부, 최근 지출, 분류·수단 목록, 마지막 대조일. 2차부터 할 일 포함 |
| `add_expense` | 1차 | id, amount, category, method, memo, date | 새 `summary` |
| `delete_expense` | 1차 | id | 새 `summary` |
| `widget` | 1차 | — | 오늘까지 쓸 돈, 기준 시각. 2차부터 가장 가까운 할 일 |
| `sprites` | 1차 | — | 드라이브 폴더의 마스코트 이미지 |
| `add_todo`, `complete_todo`, `delete_todo` | 2차 | — | 새 `summary` |
| `add_repayment` | 2차 | date, amount, memo | 새 `summary` |
| `add_income` | 2차 | date, amount, kind, memo | 새 `summary`. 1차에서는 Claude가 `수입` 탭에 직접 적는다 |
| `analysis` | 3차 | — | 분류별·날짜별 집계, 월말 예상, 빚 완료 예상, 자산 추이 |

지출 id는 화면이 만든다. 같은 id가 다시 오면 서버는 한 번만 기록한다. 그래서 신호가 나쁠 때 다시 보내도 중복이 안 생긴다. 쓰기는 `LockService`로 한 번에 하나씩 한다.

### 4.4 화면 동작

- 입력은 누르는 즉시 화면에 반영하고(같은 `Calc`로 다시 계산), 서버 응답이 오면 그 값으로 맞춘다. 전송에 실패하면 기기에 대기열로 두고 다시 보내며, 대기 중인 건수를 화면에 보여 준다.
- 기록 직후 "방금 것 취소"를 누를 수 있다.
- 5분마다 갱신하고, 화면을 다시 볼 때 30초 넘게 지났으면 바로 갱신한다.
- 토큰은 기기마다 한 번 입력해 `localStorage`에 둔다. 위젯은 Scriptable 키체인에 둔다.
- 주소 뒤에 `?demo`를 붙이면 서버 없이 예시 숫자로 전부 동작한다(입력도 메모리 안에서 된다). 예시 숫자는 실제 값과 무관한 것으로 쓴다.
- 폭 900px 미만은 폰 화면(1열, 숫자와 입력이 먼저), 그 이상은 보드.
- 위젯 갱신 시점은 iOS가 정해서 방금 입력한 지출이 바로 안 보일 수 있다. 위젯에 "HH:MM 기준"을 적는다.

### 4.5 옛 코드에서 가져올 부품

토큰 입력 화면과 흐름, `text/plain` POST 요청, 스프라이트를 드라이브에서 받아 하루 동안 캐시하는 방식, 정수 배율 확대, 토큰 글자 비교(`isValidToken_`), 날짜를 시트 시간대 문자열로 바꾸는 `toPlain_`, 색 변수와 갈무리 폰트 설정, 재포커스 갱신.

## 6. 디자인

기본 규칙은 `CLAUDE.md`의 "디자인 규칙"이다. 이번에 더하는 기준:

- 게임 말투와 마스코트는 상태 문장 창 한 곳에만 쓴다. 숫자, 표, 입력 버튼, 분석 그래프는 꾸밈 없이 읽히는 쪽을 택한다.
- 본문 글자와 바탕의 대비 4.5:1 이상, 누르는 곳은 44×44px 이상, 금액 입력은 숫자 키패드가 뜨게.
- 보드는 32인치 외부 모니터에서 스크롤 없이 한 화면. 가장 작은 글자도 팔 길이에서 읽혀야 한다.
- 화면 작업마다 `frontend-design:frontend-design`으로 방향을 잡고, `impeccable`의 critique → audit → polish를 돌린다. 분석 그래프는 `dataviz`를 먼저 읽는다.
- 화면 작업의 검증은 내장 브라우저에서 폰 폭(375)과 넓은 폭(1920 이상) 스크린샷을 찍어 사용자에게 보여 주는 것까지다.

## 7. 검증

- `Calc`는 테스트를 먼저 쓴다(`test-driven-development` 스킬). 3.1의 검증 예시 두 개, 쉬는 날에 숫자가 그대로인 것, 28·30·31일 주기, 주기시작일이 1이 아닌 경우, 지출 0건, 초과(음수), 교통 분류 제외, 방학에 걸친 주기, 쉬는날예산이 0보다 큰 경우를 포함한다.
- 서버는 배포한 주소에 실제로 요청해서 확인한다. 시험 기록은 메모를 `테스트`로 넣고 같은 id로 지운 뒤 지출 탭이 원래대로인지 본다.
- 화면은 `?demo`로 먼저, 그다음 실제 서버로 확인한다. 토큰은 사용자가 로컬 미리보기 화면에 직접 입력한다. 실행 세션은 토큰 값을 읽거나 옮겨 적지 않는다.
- 위젯과 아이폰 홈 화면 추가는 사용자만 확인할 수 있다. 작업 끝에 확인할 것을 모아서 준다.

## 8. 경계

**항상**
- 커밋 전에 `node --test tests/*.test.js` 통과. 커밋 메시지는 한국어.
- 시트 탭 구조를 바꾸기 전에 드라이브에 사본을 만든다.
- 임시로 넣은 값은 시트 설명 칸과 답변 양쪽에 "임시"라고 적는다.
- 사용자에게 설명할 때는 한국어, 결과부터, 코드 용어 없이.

**먼저 묻는다**
- `git push`(= 배포), 시트 탭 구조 변경, 3절의 돈 규칙 변경, 새 도구나 외부 서비스 추가, 범위 밖 기능.
- 사용자만 할 수 있는 일(구글 로그인·권한 허용, Scriptable 설치, 토큰 입력, 위젯 추가)은 한 번에 모아서 부탁한다.

**하지 않는다**
- 실제 금액, 시트 주소, 토큰, 마스코트 이미지 파일을 레포·커밋 메시지·PR에 넣는 일. 이런 것은 `local-notes/`, 스크립트 속성, 사용자 드라이브에만 둔다.
- 이체·결제 같은 돈 이동. 사용자가 직접 한다.
- 구독을 줄이자는 제안을 먼저 꺼내는 일.

## 11. 실행 방법

- 실행은 Opus 5.5(effort high) 세션이 한다. 준비+1차, 2차, 3차를 각각 한 세션으로 하고, 앞 단계의 체크포인트를 사용자가 승인한 뒤 다음 세션을 시작한다.
