# XG5000 삼거리 신호등 (XGK) — 회로도 + 튜토리얼

과제: 북·남·서(왼쪽) 신호등 삼거리를 XG5000 래더로 구현.
평가 문구: **"현장에서 사용 불가능한 복잡한 계산식이 들어가지 않으면서, 최적화되어 있으며 한눈에 어떻게 돌아가는지 보기 쉬운 래더"**

이 문서는 ① 과제 해석 → ② 설계 원리 → ③ 완성 래더 → ④ XG5000에서 치는 순서 → ⑤ 시뮬레이터 확인 → ⑥ 검산 → ⑦ 가정·미확인 순서다.
그림은 전부 `img/` 폴더에 있고, 번호가 문서 순서와 같다.

## 1. 과제 조건 → 시간표

조건 원문 그대로:

- 남쪽: 직진만. 초록 30, 주황 10, 빨강 30+20 (좌회전과 빨강 신호 받을 때 모두 빨강). 우회전 신호 없음.
- 북쪽: 좌회전 + 직진. 좌회전 → 초록 → 주황 → 빨강. 30, 10, 30, 20초.
- 서쪽(왼쪽): 좌회전만. 좌회전 → 주황 → 빨강. 북·남이 초록이거나 좌회전일 때 빨강, 북·남이 다 빨강일 때 좌회전. 주황 램프 포함.

이걸 한 사이클 90초, 5단계로 정리하면:

| 단계 | 시간 | 북쪽 | 남쪽 | 서쪽 |
|---|---|---|---|---|
| 1 | 0~30 (30초) | **좌회전 ←** | 빨강 | 빨강 |
| 2 | 30~60 (30초) | **초록** | **초록** | 빨강 |
| 3 | 60~70 (10초) | **주황** | **주황** | 빨강 |
| 4 | 70~80 (10초) | 빨강 | 빨강 | **좌회전 ←** |
| 5 | 80~90 (10초) | 빨강 | 빨강 | **주황** |

- 남 빨강 = 단계1(북 좌회전 30초) + 단계4·5(20초) = 50초 ✓ "30+20"
- 북 빨강 = 단계4·5 = 20초 ✓, 북 좌회전 30·초록 30·주황 10 ✓ (합 90)
- 서 좌회전은 북·남이 둘 다 빨강인 단계4·5 안에서만 ✓

![01](img/01_과제해석_삼거리_5단계.png)
![02](img/02_타임차트.png)

**내가 정한 것(조건에 숫자가 없음) — 확인 필요**

1. 북쪽 순서를 **좌회전 → 초록(직진) → 주황 → 빨강**으로 잡았다. 조건의 "좌회전이 켜지고 직진이 켜진 뒤에 빨간불" 문장과 "좌회전 초록 주황 빨강" 나열 순서를 따른 것. 시간 "30, 10, 30, 20"은 남쪽 표기(30,10,30+20)와 같은 사이클 순서(초록30·주황10·좌회전30·빨강20)로 읽었다. 글자 그대로 "좌회전30·초록10·주황30·빨강20"으로 읽으면 주황이 30초라서 비현실적이라 그렇게 읽지 않았다.
2. 서쪽 20초를 **좌회전 10초 + 주황 10초**로 나눴다. 다른 신호등 주황이 10초라서 맞춘 값. 바꾸려면 `TON T0003`·`TON T0004` 설정값만 바꾸면 된다(합이 200이면 됨).
3. 도로 모양(가지가 서쪽, 북쪽 신호등 = 남→북 차량이 봄)은 "방향은 신호등이 있는 곳 기준"에서 추론한 것. **PLC 프로그램은 도로 모양과 무관하게 위 표만 따른다.**

사진(IMG_5219.HEIC)은 이 세션에서 열 수 없었다. 사진에 타임차트나 순서가 적혀 있으면 위 1·2번과 대조해 볼 것.

## 2. 설계 원리 — 왜 이 구조인가

![03](img/03_동작원리_타이머체인.png)

**구조: 타이머 체인(5개) → 단계 릴레이(5개) → 램프(10개)**

1. **타이머 체인** — TON 5개를 줄줄이 잇는다. 앞 타이머의 접점이 다음 타이머의 입력. TON은 입력이 켜진 뒤 설정시간이 지나면 접점이 켜지고, 입력이 꺼지면 접점도 꺼지고 현재값 0 (명령어집 4-31). 마지막 T0004가 켜지는 순간 L0의 T0004 b접점이 열려 T0000이 리셋 → 뒤따라 전부 리셋 → 처음부터. 명령어집 [예제 4.6] 플리커 회로(4-32)와 같은 원리다(그림 ㉓).
2. **단계 릴레이 M** — "앞 타이머는 끝났고(a접점) 내 타이머는 아직(b접점)" = 지금 이 단계. 접점 2개(양 끝 단계는 1개)로 끝난다.
3. **램프 P** — 램프마다 "켜지는 단계의 M 접점"을 나열. 두 단계 이상이면 Ctrl+3 병렬.

**평가 문구와 대응**

| 평가 문구 | 이 래더 |
|---|---|
| 복잡한 계산식 없이 | 비교(`>=`, CMP)·연산(ADD 등) 명령 0개. 타이머·접점·코일만. 시간은 단계마다 **자기 시간만** 적는다(300, 300, 100, 100, 100). 누적값(300·600·700…)을 계산할 필요 없음 |
| 최적화 | 타이머 5개, M 5개, P 10개. 같은 코일 중복 없음(이중 코일 0). 시간 변경 = 숫자 하나 |
| 한눈에 | A·B·C 세 덩어리 + 설명문. 변수 이름(`단계1끝`, `단계2_직진`, `북_빨강`)을 켜면 램프 줄이 "단계4 또는 단계5면 북_빨강"으로 그대로 읽힌다 |

**저번 세션 버전(보류한 것)과 차이** — 저번 것은 타이머 1개(900)를 돌리고 `>= T0000 300` 같은 비교 명령 4개로 "몇 초 지났나"를 만들었다. 줄 수는 13줄로 적지만 비교 명령이 바로 "계산식"으로 읽힐 수 있고, 램프 줄마다 a·b 접점 조합을 머릿속에서 번역해야 했다. 이번 것은 비교 명령을 없애고 단계 릴레이를 둬서 줄 수는 늘었지만(26줄) 줄 하나하나가 한 문장이다. 타임차트는 두 버전이 동일하다.

### 니모닉(IL) 표 — 래더와 1:1

```
L0   LOAD NOT T0004          TON  T0000  300     ; 단계1: 북 좌회전 30초
L1   LOAD     T0000          TON  T0001  300     ; 단계2: 직진 초록 30초
L2   LOAD     T0001          TON  T0002  100     ; 단계3: 주황 10초
L3   LOAD     T0002          TON  T0003  100     ; 단계4: 서 좌회전 10초
L4   LOAD     T0003          TON  T0004  100     ; 단계5: 서 주황 10초 → 켜지면 L0 리셋
L5   LOAD NOT T0000                        OUT  M00000   ; 단계1_북좌
L6   LOAD T0000  AND NOT T0001             OUT  M00001   ; 단계2_직진
L7   LOAD T0001  AND NOT T0002             OUT  M00002   ; 단계3_주황
L8   LOAD T0002  AND NOT T0003             OUT  M00003   ; 단계4_서좌
L9   LOAD T0003                            OUT  M00004   ; 단계5_서주황
L10  LOAD M00000                           OUT  P00020   ; 북_좌회전
L11  LOAD M00001                           OUT  P00021   ; 북_초록
L12  LOAD M00002                           OUT  P00022   ; 북_주황
L13  LOAD M00003  OR M00004                OUT  P00023   ; 북_빨강  (L13+L14)
L15  LOAD M00001                           OUT  P00024   ; 남_초록
L16  LOAD M00002                           OUT  P00025   ; 남_주황
L17  LOAD M00000  OR M00003  OR M00004     OUT  P00026   ; 남_빨강  (L17~L19)
L20  LOAD M00003                           OUT  P00027   ; 서_좌회전
L21  LOAD M00004                           OUT  P00028   ; 서_주황
L22  LOAD M00000  OR M00001  OR M00002     OUT  P00029   ; 서_빨강  (L22~L24)
L25  END
```

## 4. 주소표

![08](img/08_주소표_변수이름.png)

- T0000~T0999는 기본 파라미터 그대로면 **100ms 타이머** (명령어집 2-34, XG5000 매뉴얼 9-4). 300 = 30.0초.
- 출력 번호는 I/O 파라미터로 정해진다. 위 표는 슬롯0 입력 32점, 슬롯1 출력 32점(5주차 자료 p.9 구성) 기준 → 출력 P00020부터. 입력 16점·출력 16점을 넣으면 출력은 P00010부터이므로 `P0002x → P0001x`로 바꿔 친다. 확실치 않으면 I/O 파라미터 창의 "할당 정보" 열이나 시스템 모니터에서 주소를 본다.

**자주 하는 실수**

- 타이머 번호 중복/순서 꼬임 → 체인이 끊겨 어느 단계에서 멈춘다. L0~L4의 T 번호가 0→1→2→3→4인지 확인.

## 7. 검산

`도구/sim.py`(Python)로 래더를 스캔 단위(10ms)로 300초 흉내 냈다. 결과 `도구/검산_결과.txt`:

- 어느 스캔에서도 단계 릴레이는 정확히 1개만 ON (위반 0)
- 각 신호등은 항상 램프 정확히 1개만 ON (북·남·서 모두 위반 0)
- 북 좌회전 중 남 초록 0회, 서 좌회전 중 북·남 빨강 아닌 경우 0회, 북·남 초록/좌회전 중 서 빨강 아닌 경우 0회
- ON 구간 길이: 북 좌회전 30 / 북·남 초록 30 / 주황 10 / 북 빨강 20 / 남 빨강 30·50 / 서 좌회전 10 / 서 주황 10 / 서 빨강 70, 주기 90초

리셋 순간: T0004가 켜지는 스캔에 M00004(=T0003)는 그대로 ON이고, 다음 스캔에 L0에서 체인이 리셋되면서 M00000이 ON으로 바뀐다. 램프가 전부 꺼지는 스캔은 없다(검산 결과와 일치).

## 9. 확인된 것 / 확인 못 한 것

**매뉴얼로 확인한 것**

- TON 문법·동작(입력 Off → 출력 Off·현재값 0), 설정시간 = 기본주기 × 설정치: XGK/XGB 명령어집 V2.3 4-31, 플리커 예제 4-32
- 100ms 타이머 기본 영역 T0000~T0999: 명령어집 2-34, XG5000 매뉴얼 V3.0 9-3~9-4
- 디바이스 범위(XGK P/M 00000~2047F, T 0000~2047): 명령어집 2-13
- 단축키 F3/F4/F5/F6/F9/F10/Ctrl+3/Ctrl+4: XG5000 매뉴얼 5-1~5-2
- 응용명령 입력(F10 → 입력 → 확인), 코일·출력 명령은 가로선 자동, 이중 코일은 마지막 값: 5-11~5-13
- OR 접점은 커서 위 접점과 병렬, Enter는 직전과 같은 종류 재입력, 즉시 입력 모드 옵션: 5-4
- 변수/설명 추가 창, 변수 이름 규칙: 5-6, 4-4
- I/O 파라미터 열기·모듈 선택·가변 할당 표(32점 입력 다음 출력은 P00020부터): 9-7~9-10
- 시뮬레이터 시작 → 런, 시스템 모니터는 I/O 파라미터 모듈만 표시: 15-2, 15-21
- 모니터 색(a접점 1=파랑, b접점 0=파랑): 11-6~11-7

**확인 못 한 것 / 기억·추정**

- END가 XGK 새 프로젝트에 자동으로 들어가는지 — (기억 의존). 없으면 빈 줄에서 F10 → `END`.
- 실습실 CPU 기종·I/O 모듈 — 스킬에 적힌 0929 노트(XGK-CPUS/CPUSN, 16점 입력)와 5주차 p.9(32점·32점)가 다르다. 이 문서는 32점·32점 기준. 다르면 4절대로 주소만 바꾼다.
- 과제 사진 내용 — 못 봄. 1절 "내가 정한 것" 1·2번을 사진과 대조할 것.
